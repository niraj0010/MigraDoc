# MigraDoc JSON report example

A small .NET 9 console app that turns a JSON report response into a clean, paginated PDF using MigraDoc document elements (paragraphs, styles, tables, cells, and footers).

## Package and compatibility

The project uses [`PDFsharp-MigraDoc` 6.2.4](https://www.nuget.org/packages/PDFsharp-MigraDoc/6.2.4), the latest stable release at the time this example was created. It is the cross-platform Core package and brings in its matching PDFsharp dependency. Official package metadata lists `net8.0`, `net9.0`, `net10.0`, and `netstandard2.0` compatibility.

This repository targets `net9.0` because the available SDK is .NET 9. The package is compatible with .NET 10; change the `TargetFramework` in both project files to `net10.0` after installing the .NET 10 SDK. The Core package needs explicit font configuration from PDFsharp 6.2 onward. This example opts into Windows system fonts, which is suitable for this Windows sample. A cross-platform production deployment should provide and register a custom PDFsharp font resolver with its licensed font files.

## Run it

From the repository root:

```powershell
dotnet restore
dotnet test
dotnet run --project src/MigraDocReport -- sample/report.json output/pdf/report.pdf
```

The generated file is `output/pdf/report.pdf`.

## Credit report layout

The credit-report command uses the purpose-built `CreditReportResponse` contract: customer name and address, a single four-column credit-profile summary, one row per bureau, and a column-driven references table. The included values are fictional sample data and are not a consumer report.

```powershell
dotnet run --project src/MigraDocReport -- credit sample/credit-report.json output/pdf/credit-report.pdf
```

The generated credit-report sample is `output/pdf/credit-report.pdf`.

## JSON shape

`sample/report.json` provides the expected response format. It has a title, an arbitrary-length `kpis` array, column definitions, and rows. A row is an object keyed by each column's `key`; values can be strings, numbers, booleans, or null.

`widthWeight` is a relative width, while `alignment: "right"` is useful for numeric columns. Missing values render as an em dash. Long unbroken tokens receive soft break opportunities so a narrow cell remains readable. MigraDoc performs normal paragraph wrapping and automatic page breaking; the table header is marked as a repeating heading when the table continues onto another page.

## Layout behavior

- KPI cards are generated by iterating the input list and flow into rows of up to three cards.
- Table columns and rows are generated entirely from the JSON response.
- Empty KPI, column, and row collections receive a readable in-report message.
- The PDF test builds 90 rows and asserts that the rendered report spans more than one page.
